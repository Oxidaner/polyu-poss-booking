## 从「抢一节体育课」扩到「抢所有 fitness」：Activity 维度 + 本地选课 UI
用户需求：POSS 的 make_book.do 页面有 Activity / Date / Center 三个下拉框，
要求这三个都能自己选，并要一个「像 POSS 那样点选要抢哪一节课」的 UI。

### 先说数据模型（这才是真问题）
原代码把 X123/X202 焊在 `gyms` 里、`actvId:101`/`dataSetId:18` 当常量 ——
所谓「Activity 下拉框」在代码里根本不存在。所以先做模型改造，UI 只是表皮。

### 新增 `booking.targets`（显式目标）
- 每项：`{ctrId, name, date, from, to, activity, actvId, dataSetId}`
- **放位日 = 目标日期 − lead_days 的 trigger_time**（POSS 只放今天起 8 天）。
  `_target_release_dt()` / `plan_jobs()` / `_job_from_target()` / `slot_matches_job()`。
- 非空时 `booking_phase` 不再看 `trigger_days`，只看「今天是不是某个目标的放位日」。
  Actions 的 `29 0 * * *` cron 本来就是**每天**跑，所以任意放位日都能接住。
- 空时保持旧的派生逻辑（今天+lead_days、同星期几、全部馆）—— 旧配置零改动。
- **抢到一个目标不再收工**，继续抢下一个（要抢多节）；只有 `inconclusive` 才全线停手。
- 去重从「按日」改成「按目标」：`state["booked_targets"]["{ctrId}|{date}|{from}"]`。
- 蹲守范围跟随 targets：`watch_scopes()` 返回 targets 里出现过的 (ctrId, actvId, dataSetId) 组合，
  `fallback_targets()` 带上精确日期。

### 新增 `poss_ui.py`（本地选课 UI）
- 本地 `http.server`（只绑 127.0.0.1，端口 8765）+ 单页 HTML，无新增依赖。
- `/api/meta` 登录后抓 `make_book.do` → `parse_selects()` 解析所有 `<select>` →
  按 name 关键词归角色（activity/dataset/center/date/other）。
- `/api/timetable` 拉时间表 → `build_grid()` 摊成 日期×时段 网格；
  `/api/targets` 校验后写回 config.json。
- 配色对齐 POSS：灰=不可用 / 洋红=$0+可退押金 / 蓝=收费 / 浅蓝=价格未知 / 极浅=原始数据没这个时段。
- 每个目标 chip 显示它自己的放位日，避免「点了 10-14 却不知道要 10-07 去抢」。

### 踩到的坑（都值得记住）
1. **`_parse_date()` 返回 `date` 不是 `datetime`** —— 新调度代码写 `.date()` / `.replace(hour=)`
   直接崩。写日期计算前先确认这个。
2. **UI 网格的列不能拿页面 date 下拉框的选项**。POSS 那个框是「搜索起始日」，
   选项可能只有两三条；照它画会缺列。正确做法：列 = 从选定起始日算 8 天。
3. **抓来的 `selected` 状态重建 option 时会丢**。`fillSelect` 必须显式
   `o.selected = true`，否则 Activity 停在「-- 请选择 --」上，保存出去的目标没有活动。
4. **灰色格子必须可点**。现在不可订 ≠ 放位那刻不可订；抢位目标本来就是给未来定的。
   一开始做成 `cursor:default` 会让整个 UI 在窗口没开时完全没用。
5. 裸属性 `<option selected>` 没有 `="..."`，`_attrs` 正则抓不到，要单独判 `"selected" in attrs_text`。
6. `_validate_booking_targets` 校验失败时**不能落盘**，否则 Actions 里直接炸。
7. 两个模块各自维护 `CONFIG_FILE` 会分叉 → 统一成 `poss_ui.config_path()` 读 `M.CONFIG_FILE`。
